# 案件工作台（办案操作系统 · 总入口）

> 角色：总入口 / 派发器　｜　负责：案件目录、阶段推进、产出落盘、看板　｜　不负责：具体专业动作（那些交给 5 个专项技能）

## 0. 这个技能解决什么

五个程序各干各的，结果就是：**材料找不到、进度说不清、AI 每次都要重新讲一遍案情**。

这个技能把它们串成一个"工作台"：**一个案子 = 一个文件夹**，每份产出按路径落盘，每个阶段用 Checklist 打勾，谁接手都能一眼看到卡在哪。

**输入**：案件基本信息（谁告谁、案由、金额、管辖、承办律师）。
**产出**：`案件-<编号>-<原告>诉<被告><案由>/` 目录树 + `00-案件档案/案件基本信息.md` + 看板一行。

## 1. 铁律（违反即失败）

1. **一个案子一个文件夹，产出必须落盘**。只写在对话里、不进文件夹的产出等于没做——下周没人找得到。
2. **先建台，再跑程序**。没有 `00-案件档案/案件基本信息.md` **和** `00-案件档案/案件台账.md` 的案件，不允许启动任何专项技能（没有基本信息和编号台账，AI 只能靠猜、编号必然错位）。
3. **当前阶段只有一个，下一个动作必须有日期**。"取证中 + 补银行流水 + 2026-11-15" 才叫可执行；"推进中"不算状态。
4. **AI 产出是草稿**。所有报告、文书必须执业律师审核、签字、盖章才能对外；法条与案号必须二次核验。
5. **隐私按最小必要留存**。当事人身份证号、手机号只在 `00-案件档案/案件基本信息.md` 里留，往任何外部 AI、平台、群聊发送前先脱敏。
6. **只追加不覆盖**。`07-程序记录/案件时间线.md` 只往后写，改错了补一行说明，不删历史。
7. **编号只有一个出处**。待证事实 `TF-01`…、证据 `E-01`…、争点 `IS-01`… 只在 `案件台账.md` 定义；任何报告、目录、文书里出现的编号都必须能在台账找到对应行。**台账校验不通过，不许派发下一个技能。**

## 2. 触发条件与输入检查

### 2.1 两种模式

| 模式 | 用户说什么 | 做什么 |
|---|---|---|
| **建台** | "新案子进来""建个案件文件夹""这个客户签了" | 建目录树 + 填基本信息 + 看板加行 + 报下一步 |
| **查台** | "这个案子到哪一步了""卡在哪""下周该干什么" | 读基本信息 + 时间线 + Checklist，报进度/卡点/下一步 |

### 2.2 建台的输入检查（缺必填项先问，别猜）

| # | 输入项 | 必填？ | 缺了怎么办 |
|---|---|---|---|
| 1 | 案件编号（`年份-序号`，如 2026-015） | 必填 | 问；不知道就取当年看板最大序号 +1 |
| 2 | 案件名称（`原告诉被告案由`） | 必填 | 问当事人姓名与案由 |
| 3 | 案由 | 必填 | 问；只给大类（如"借贷"）时按最接近的规范案由填，标"待确认" |
| 4 | 我方当事人（原告/被告/上诉人/被上诉人） | 必填 | 问 |
| 5 | 承办律师 | 必填 | 问 |
| 6 | 收费方式与金额 | 选填 | 标"待补"，不阻塞建台 |
| 7 | 争议金额 | 选填 | 标"待补" |
| 8 | 管辖法院 | 选填 | 标"待补" |
| 9 | 工作台根目录（案子放在哪个盘） | 必填 | 问一次，之后记住这个根目录 |

**检查动作**：8/9 项必填缺 1 项 → 停下来问，不要先建一个填满"待定"的空壳。

## 3. 标准案件目录与一键建台

### 3.1 目录树（照抄，不要自创层级）

```
案件-<编号>-<原告>诉<被告><案由>/
├── 00-案件档案/        ← 基本信息、台账、交付包清单、期限台账、利益冲突审查、委托合同、授权委托书、收费凭证、生命周期Checklist
├── 01-材料收集/
│   ├── 当事人提供/     ← 身份证、转账记录、聊天截图、其他
│   ├── 律师调取/       ← 银行盖章流水、工商登记
│   └── 材料收集清单.md ← 收了什么、还缺什么
├── 02-证据整理/        ← EV-01 产出：证据目录、三性审查表、证据链图谱、质证意见、补证清单
├── 03-法律研究/        ← LR-01 产出：法律研究报告、法条摘录、类案判例/
├── 04-合同审查/        ← CR-01 产出：原合同、审查报告、修改版合同
├── 05-诉讼策略/        ← LA-01 产出：策略分析报告、庭审提纲、调解方案；另放**案件分析报告**（汇总交付，见 §4）
├── 06-文书产出/        ← LD-01 产出：起诉状、答辩状、律师函、代理词、证据目录（法院版）
├── 07-程序记录/        ← 立案通知、传票、庭审记录、判决书、案件时间线
└── 08-结案归档/        ← 结案报告、复盘记录、案卷装订目录
```

### 3.2 命名规则（全所统一，别各自发明）

| 对象 | 规则 | 例子 |
|---|---|---|
| 案件文件夹 | `案件-年份-序号-原告诉被告案由` | `案件-2026-015-张三诉李四民间借贷` |
| 证据文件 | `证据XX-日期-内容简述` | `证据01-20240315-微信转账5万元.jpg` |
| 文书 | `文书类型-日期-版本` | `起诉状-20261031-v1.docx` |
| 报告编号 | `<程序编号>-<日期>-<序号>` | `LR-20261031-001`、`LA-20261031-002` |

### 3.3 一键建台（本技能自带脚本）

```powershell
$S = "%USERPROFILE%\.dsh\skills\lawyer-case-workbench\assets\new-case.ps1"
& $S -Root "D:\案件" -CaseId "2026-015" -Name "张三诉李四民间借贷" -Lawyer "唐律师"
```

脚本做的事：建 10 个子目录 → 复制 4 个模板到位（基本信息 / 材料收集清单 / 证据目录 / 生命周期Checklist）→ 把案件编号、案件名称、承办律师、建档日期填进去 → 建 `07-程序记录/案件时间线.md` 并写第一行。

补充约定：
- 目标文件夹已存在会报错退出；确认要重建模板用 `-Force`（只覆盖模板文件，不动别的）。
- 脚本会同时生成 `00-案件档案/案件台账.md`（全案编号唯一出处）和 `07-程序记录/案件时间线.md`，并把案件编号/名称/律师填好。
- 建完必须**立刻**把 3.1 目录树和下一步念给用户确认，再进入第 4 节派发。
- 手工建目录也照 3.1 一模一样，宁可少建不要多建层级。

### 3.4 建台后必做四件事

1. 填 `00-案件档案/案件基本信息.md`（当事人、争议金额、管辖、关键时间节点）。
2. 看板加一行（第 6 节），当前阶段填"咨询中"或"已接案"。
3. 按案由勾 `01-材料收集/材料收集清单.md`，缺的写进"缺件跟进"表。
4. 填 `00-案件档案/期限与时效台账.md` 第 1、2 项（时效起算点、拟立案日），并在 `律师交付包清单.md` 里把接案前 5 项过一遍——**期限与交付包天天都要看，别等出事才想起来。**

## 3.5 案件台账（唯一数据源，全案编号只在这里定义）

**为什么要有它**：法律研究说"证据一"是微信转账、证据处理说"证据一"是聊天记录、起诉状照着其中一份写——上庭前才发现编号错位，返工要动三个文件。台账就是防止这件事的唯一真源。

**文件**：`00-案件档案/案件台账.md`，8 个表：① 案件状态 ② 待证事实 TF ③ 证据 E ④ 诉请与金额 ⑤ 争点 IS ⑥ 待补清单 ⑦ 编号校验规则 ⑧ 变更记录。

**编号规则**：`TF-01`（待证事实）/ `E-01`（证据）/ `IS-01`（争点），**与中文序号一一对应**（E-01 = 证据一，E-02 = 证据二……）。跳号、复用、作废都占位不删。

**分工**（谁写哪张表）：

| 表 | 谁写 | 何时 |
|---|---|---|
| ① 案件状态 | 工作台（本技能） | 建台时、每次阶段变化 |
| ② TF 待证事实 | `lawyer-legal-research` 首次登记；`lawyer-evidence-handling` 回写支撑状态 | LR 研究完 / EV 整理完 |
| ③ 证据 E | `lawyer-evidence-handling` 登记；`lawyer-doc-drafting` 只引用 | EV 编号时 |
| ④ 诉请与金额 | `lawyer-litigation-analysis` 定；`lawyer-doc-drafting` 引用 | LA 定策略时 |
| ⑤ 争点 IS | `lawyer-litigation-analysis` | LA 分析时 |
| ⑥ 待补清单 | 谁发现谁登记 | 任意阶段 |
| ⑧ 变更记录 | 谁改谁写一行 | 每次改动 |

**校验（派发前必跑，不通过不许往下走）**：

```powershell
$py = "python"
& $py -X utf8 "%USERPROFILE%\.dsh\skills\lawyer-case-workbench\assets\check-ledger.py" "<案件目录>"
```

校验五件事：编号唯一、连续不跳号、E 指向的 TF 存在、TF 至少挂一个证据（否则状态必须写 `断点`/`待补`）、全案文书里出现的编号都能在台账找到。**通过才派发下一个技能；不通过就把问题逐条列给律师，改完再跑。**

## 3.6 律师交付包（分析不等于交付：这些文件没有就是没办完）

5 个专项技能产出的是**判断与文书**；律师真正执业还必须有**手续和留痕**。共 22 项，分四段：接案前 5 项、签约 4 项、办案过程 9 项、结案 4 项。完整清单见 `assets/模板-律师交付包清单.md`（含"缺了会出什么事"）。

**六条红线（没有到手，不许进下一阶段）**：

| # | 文件 | 为什么是红线 |
|---|---|---|
| 1 | 利益冲突审查记录 | 冲突是执业红线，可能被撤销代理/处分 |
| 6 | 委托代理合同 | 代理权与收费的唯一依据 |
| 7 | 授权委托书（写清授权范围） | 立案必备；特别授权须逐项列明 |
| 8 | 送达地址确认书 | 送达不到可能缺席判决 |
| 11 | **期限与时效台账** | 漏期 = 实体/程序权利直接丧失 |
| 13 | 证据原件交接单 | 原件丢失是律所高额赔偿高发点 |

**三条使用规则**：

1. 建台时脚本会把 `律师交付包清单.md`、`期限与时效台账.md`、`利益冲突审查表.md`、`证据原件交接单.md` 一并复制到位；**清单前三项必须在签委托之前跑完**。
2. 期限台账**每次阶段变化必须更新一次**（收到受理通知/传票/举证通知/判决书，当天更新），不是建台填一次就完事。
3. **委托代理合同、授权委托书、风险告知书的条款文本必须用律所模板库的正式版本**——AI 只负责"提醒你必须有这一份、该填什么"，不代拟条款。这一点不得越界。

**结案前**：交付包清单必须全 `✅` 或 `—`，有 `❌` 一律退回归档。

## 4. 阶段 → 技能派发表（本技能的核心）

### 4.1 派发前置（缺一步都不许派）

1. 该案件有 `案件基本信息.md` + `案件台账.md`。
2. 台账校验通过（§3.5）。
3. 把将要派发的技能需要的**阻断级输入**点一遍，缺任何一项先回头问律师——**可待补级缺项不阻塞**，但要在产出物首屏写明"基于 N 项待补信息"。

### 4.2 咨询阶段的路由顺序（三个技能会同时命中时按此走，不许乱序）

客户一句"我这情况能不能告、大概要花多少钱"会同时命中三个技能。固定顺序：

```
① lawyer-consult-diagnose（谈案流程：咨询脚本、方案三档、报价）
        ↓ 拿到"要不要接、怎么报价"的结论
② lawyer-legal-research（法律判断：能不能告、值不值得接、走哪条路径）
        ↓ 结论"建议接" → 签委托 → 建台（本技能）
③ lawyer-deal-close（签约：异议处理、合同、收费、回款）
        ↓ 签完
④ 进入办案交付线：evidence → litigation-analysis → doc-drafting
```

**硬规则**：咨询阶段**只允许**由 `lawyer-consult-diagnose` 生成咨询记录，且咨询记录里只放 LR 报告的**编号引用**（`LR-20261031-001`），不重复抄一遍研究内容——**同一场咨询只存一处记录**，避免 CRM 与案件文件夹两套内容打架。

按用户说的场景查表 → 直接调对应技能，不要让他自己挑。

| 当前场景 | 该跑的技能 | 关键输入 | 产出落盘到 | 何时进入下一阶段 |
|---|---|---|---|---|
| 客户来咨询，判断能不能告/值不值得接 | `lawyer-legal-research` | 研究问题、身份关系、时间线、金额、管辖 | `03-法律研究/法律研究报告-LR-<日期>-<序号>.md` | 结论"建议接案"才签委托 |
| 签了委托，整理当事人零散材料 | `lawyer-evidence-handling` | 案由、待证事实、已有材料、证据形式 | `02-证据整理/证据目录.md`、`补证清单.md`、`质证意见.md` | 证据链闭环（或断点已列补证清单） |
| 客户送审合同 / 顾问单位合同 | `lawyer-contract-review` | 合同全文、合同类型、我方角色、金额期限 | `04-合同审查/审查报告-CR-<日期>-<序号>.md` | 报告 + 修改版交出 |
| 证据齐了，定策略/算胜诉概率/备庭 | `lawyer-litigation-analysis` | 时间线、我方身份、证据清单、对方抗辩、客户底线 | `05-诉讼策略/策略分析报告-LA-<日期>-<序号>.md` | 策略与调解底线经客户确认 |
| 要写起诉状/答辩状/律师函/代理词 | `lawyer-doc-drafting` | 文书类型、案由、当事人信息、事实、请求、证据清单、管辖法院 | `06-文书产出/<文书类型>-<日期>-v1.docx` | 律师审核签字盖章 |
| 收材料阶段，缺什么怎么取 | `lawyer-evidence-handling`（补证分支） | 待证事实、缺失项 | `02-证据整理/补证清单.md` | 当事人补齐后重跑 |
| 对外发送前（客户/平台/公众号） | `lawyer-compliance-guard` | 待发文案 | 命中清单 + 改写稿 | BLOCK 项清零才发 |
| LR+EV+LA 都跑完，要给律师/合伙人一份**综合判断** | 本技能（汇总分支） | 台账 + LR 报告 + 证据三件套 + 策略报告 | `05-诉讼策略/案件分析报告-CA-<日期>-<序号>.md` | 律师签字后用于谈案/内部决策 |
| 案子办完 | 本技能（第 8 节归档分支） | 全案产出 | `08-结案归档/结案报告.md` | 看板标"已结案" |

**汇总分支的硬要求**（别把汇总做成又一份长报告）：

- **一页结论放最前面**：能不能做、能拿多少（区间）、最大风险、现在最该做的三件事、明确不做什么、客户要听的实话。
- **只汇总、不新增判断**：法律判断引用 LR 编号、证据引用 E 编号、概率引用 LA 区间；汇总时不得出现 LR/LA 里没有的新结论。
- **必须带两张表**：金额测算表（本金/利息/费用/最坏到手）与下一步动作表（截止/动作/负责人）。
- **末尾必须有审核栏**与"AI 汇总草稿、法条案号待核验"标注。

派发时的固定话术结构（避免直接扔技能名给用户）：

> 现在这案子在【阶段】。这一步该做的是【动作】，用 `【技能名】` 跑，产出会落到【文件路径】。
> 开始前请给我【缺的输入】，齐了就出报告。

## 5. 数据怎么在技能之间流（谁喂谁）

不要让律师重复整理同一份事实，按这条链传：

```
LR-01 法律研究报告
   ├── 「待证事实」→ 直接作为 EV-01 的输入（不用重新拆）
   └── 「接案建议」→ 决定是否建台
              │
              ▼
EV-01 证据目录 + 补证清单
   ├── 断点 → 回 01-材料收集 催件
   └── 证据编号 → 直接喂 LD-01「事实段落标注（见证据X）」
              │
              ▼
CR-01 合同审查报告（如涉及合同）
   └── 「风险条款清单」→ 喂 LA-01 争点与抗辩预判
              │
              ▼
LA-01 策略分析报告
   ├── 「诉讼请求怎么定」→ 喂 LD-01 请求部分
   ├── 「调解底线」→ 客户确认后才允许谈判
   └── 「庭审提纲」→ 开庭当天用
              │
              ▼
LD-01 起诉状/答辩状/代理词 → 07-程序记录 立案、开庭、判决
```

三条硬规则：
1. **编号贯通**：证据编号一旦定了，后续所有文书、目录、庭审提纲都用同一套编号，不许重编。
2. **报告带编号**：每份报告首行写 `<程序编号>-<日期>-<序号>`，回填到 `00-案件档案/案件基本信息.md` 的"关联文件"清单。
3. **换人接手只读三样**：`案件基本信息.md` → `案件时间线.md` → Checklist。这三样读不出进度，说明工作台没建好。

命令（脚本在 `assets/case-board.py`）：

```powershell
$py = "python"
$S  = "%USERPROFILE%\.dsh\skills\lawyer-case-workbench\assets\case-board.py"
$U  = "https://<YOUR_TENANT>.feishu.cn/wiki/<WIKI_NODE_TOKEN>"

& $py -X utf8 $S ensure-schema --target $U    # 补齐 12 个字段（已存在就跳过）
```

## 7. 生命周期 Checklist 怎么用（含"卡在哪"诊断）

`00-案件档案/案件生命周期Checklist.md` 是每个案子的进度真相源，阶段顺序固定：

```
咨询 → 接案 → 取证 → 策略 → 立案 → 庭前准备 → 庭审 → 判决 → 执行（如需） → 结案归档
```

**用法**：完成一项打勾；**不许跳项**，跳项必须在时间线里写原因（例如"对方同意调解，判决/执行阶段关闭"）。

**"卡在哪"诊断法（查台模式照此回答）**：

1. 读 Checklist，找**最后一个已打勾的阶段** → 当前阶段。
2. 看该阶段**第一个未打勾项** → 卡住的具体动作。
3. 查 `07-程序记录/案件时间线.md` 最后一行日期 → 距今多少天。
4. 判定：
   | 现象 | 诊断 | 处置 |
   |---|---|---|
   | 某项 7 天没动 | 单点卡住 | 直接催这一项，写进"下一个动作"并给日期 |
   | 阶段内 30 天没动 | 阶段卡住 | 加一次当事人沟通，确认材料/判决/对方态度是否有变 |
   | Checklist 整段空白 | 工作台没维护 | 从时间线倒推补勾，再定下一步 |
   | 已打勾但文件夹没产出 | 打勾造假 | 以文件为准撤销打勾，重跑对应技能 |

**查台前先跑台账校验**（§3.5）：编号对不上、文书引用了台账里没有的证据时，Checklist 的勾一律不可信——先把台账修好再看进度。

**结案归档**（第 8 节路径）：结案报告写清结果与回款 → 复盘记录写清"这个案子踩了什么坑、下次怎么改" → 案卷装订目录按 `00→08` 顺序列 → 看板改"已结案"。
