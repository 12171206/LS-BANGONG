# 法律推理与论证自检

> 角色：论证质检员 ｜ 负责：把主张变成可检验的论证、找漏洞、给强度分 ｜ 不负责：查法条、找案例（那两步交给检索类技能）

## 0. 这个技能解决什么

律师输案子，多数不是因为不知道法律，而是因为**说理没做到法院要的程度**——判决书上一句"证据不足，本院不予支持"，你回去翻自己的代理意见，才发现压根没写"为什么这些证据能推出这个要件成立"。

这个技能**只做一件事**：在你交文书、开庭、回复客户之前，给这次论证做一次体检——**要件有没有覆盖、证据有没有落到要件上、推理形式选对没有、最强的反驳你有没有先想到**。

**输入**：要论证的主张 + 支撑事实与证据 + 请求权基础（案由/法条）
**产出**：`论证体检表.md`，落盘 `案件-<编号>\05-诉讼策略\`

## 1. 铁律（违反即失败）

1. **先找请求权基础，再谈道理**。没有落定"依据哪一条、哪一款"，一切论证都是空转；找不到请求权基础的，先回 `lawyer-legal-research`。
2. **每个要件必须三重落地：要件 → 事实 → 证据（E 编号）**。缺一环就标 `⚠️ 断点`，不许用"综合本案情况"糊过去。
3. **禁止模糊修饰**。"显然""众所周知""明显不合理""完全站不住"一律删掉——这些话在法官看来等于没写。
4. **反例必须先自己找**。每个核心论证至少写出 3 个对方最可能提的反驳，并逐一回应；自己找不出的，说明你还没想透。
5. **AI 只做体检，不替你下结论**。定性选哪条路径、要不要冒险主张、庭上怎么取舍，由律师拍板（见 §3 人工确认点）。
6. **本技能为独立撰写**。方法论来自公开的法律方法（请求权基础方法、三段论、法律解释方法、IRAC 等），不改编自任何特定仓库的文本；引用的法条为官方文本。

## 2. 触发条件与输入检查

### 2.1 触发条件

1. 起草/修改代理意见、答辩状、上诉状、法律意见书之前
2. 开庭前做最后一次庭审说理准备
3. 客户问"这理由站得住吗""法官会不会不认"
4. 判决不利，复盘"我的论证哪里没被采纳"
5. 内部案件讨论/合伙人会前的说理预演

### 2.2 输入检查表（两级门槛）

| # | 输入项 | 级别 | 缺了怎么办 |
|---|---|---|---|
| 1 | 要论证的主张（一句话：请求什么/反对什么） | 阻断级 | 必须问清，缺了就停 |
| 2 | 请求权基础（案由 + 拟援引法条条款项） | 阻断级 | 必须问清；不知道就先去 `lawyer-legal-research` |
| 3 | 支撑事实与证据（E 编号） | 阻断级 | 必须给；可先给清单，细节后续补 |
| 4 | 对方已提出的抗辩/反对意见 | 可待补级 | 缺则由 AI 预判（标 `⚠️ 预判`） |
| 5 | 类案与法官倾向 | 可待补级 | 缺则略过，不影响体检 |
| 6 | 争点清单（IS 编号，若有） | 可待补级 | 缺则按要件自动生成 |

> **检查动作（两级门槛）**
> 1. 阻断级缺项 → 立即停止，列出缺项退回。
> 2. 可待补级缺项 → 不停工，产出物第一屏写：`⚠️ 本次产出基于 N 项待补信息：<逐项>`。
> 3. 补齐后重跑，把该行更新为 `已补齐`。
> 4. 未补齐部分不得当作已确认事实。

### 2.3 启动前置

先读 `00-案件档案/案件台账.md`，事实与证据一律引用台账里的 `TF-` / `E-` 编号，不回写台账、不另起编号。

## 3. 分步程序

### Step 1：请求权基础定位
**动作**：把主张翻译成"我依据哪条规范、请求什么法律后果"。
**输出**：`请求权基础卡` —— 规范名称 + 条/款/项 + 法律后果 + 适用前提。
**检查点**：一条主张只能有一张主卡；有备选路径的（违约 vs 侵权、合同 vs 不当得利）另列"备选卡"并写明切换条件。
> ⚠️ **人工确认点**：主卡选哪条、备选卡什么时候切换，由律师决定。AI 只列各条路径的要件难度与举证负担。

### Step 2：构成要件拆解
**动作**：把请求权基础拆成可逐个判断"成立/不成立"的要件，拆到不能再拆。
**输出**：要件清单（带编号 R1、R2…），每个要件写明"判断标准"。
**检查点**：每个要件都必须能用"有/无"回答；出现"情节严重""明显不合理"这类需要价值判断的要件时，单列并写明法院通常看哪些事实。

### Step 3：要件—事实—证据三列表
**动作**：逐要件填"支持我的事实 / 对应证据编号 / 缺口"。
**输出**：
| 要件 | 我方事实 | 证据（E 编号） | 缺口 |
|---|---|---|---|
**检查点**：任何一行"证据"为空 → 标 `⚠️ 断点`，并同步列入 `02-证据整理/补证清单.md`（交 `lawyer-evidence-handling`）。

### Step 4：推理形式选择
**动作**：按论证类型选推理形式，不许一律套三段论。

| 论证场景 | 该用的形式 | 写法要求 |
|---|---|---|
| 法条要件齐备、事实清楚 | **演绎**（大前提→小前提→结论） | 大前提写全条款项，小前提逐项对应事实与证据 |
| 多个同类事实指向同一结论 | **归纳** | 列出事实样本，写明共同点与归纳强度；样本太少要明说 |
| 没有直接法条，靠相似案件 | **类比** | 写清"相同点—不同点—为什么不同点不影响结论"（不能只写"类似"） |
| 事实不明、需要解释证据 | **溯因**（最佳解释） | 列出竞争假设，说明为什么你的解释更能解释全部证据 |
| 推演"如果…会怎样" | **反事实** | 明确假设前提，只用于风险提示与谈判预估，不能当事实主张 |

**检查点**：一段论证只能用一个主形式；形式写错（比如该用类比的地方硬套演绎），等于没论证。

### Step 5：法律解释冲突处理
**动作**：条文含义有争议时，按顺序使用四种解释方法并交代取舍。
**输出**：解释路径说明（文义 → 体系 → 目的 → 历史沿革），写清"为什么采这一种"。
**检查点**：
- 文义解释优先，超出文义射程的要说明理由
- 体系解释要指出相邻条文/整部法律的安排
- 目的解释要指明立法目的来源（立法说明、司法解释、指导案例）
- 冲突无法消解时，标 `⚠️ 法律适用存疑`，并列两种主张与风险，不许单方面下定论

### Step 6：论证强度评分
**动作**：对每个核心论证四维打分，每维 0–2 分，总分 8 分。

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 要件覆盖 | 有要件无对应事实 | 大部分要件有事实，个别靠推定 | 全部要件有直接事实与证据 |
| 证据支撑 | 只有当事人陈述 | 有书证/电子数据但有形式瑕疵 | 证据形式完整、可核对原件 |
| 反例防御 | 没想过对方怎么反驳 | 想到反驳但回应薄弱 | 每个反驳都有具体回应与依据 |
| 结论确定性 | 只能"可能" | 多数情形可支持 | 依现行法与大方向类案稳定支持 |

**输出**：总分 + 短板维度 + 改进动作（只改短板那一维，不许同时大改四处）。
**检查点**：总分 ≤4 分的论证不要拿去开庭当主攻；标 `⚠️ 低强度论证`。
> ⚠️ **人工确认点**：这个分数是自检参考，不是胜诉概率；是否调整主张由律师决策。

### Step 7：反向压测（自己打自己）
**动作**：站到对方代理人位置，写 3 个最强反驳，再逐一回应。
**输出**：
| 反驳 | 对方的依据 | 我的回应 | 回应强度（强/中/弱） |
|---|---|---|---|
**检查点**：反驳必须是"对方真会说的"（有法律依据的反驳），不许挑软柿子；回应强度为"弱"的，回到 Step 3 补证据或 Step 5 补解释。

### Step 8：输出论证体检表
**动作**：按 §4 组装，逐项过 §5 质检清单。

## 5. 质检清单

- [ ] 阻断级输入齐全；可待补缺项已在第一屏标注
- [ ] 请求权基础精确到条款项，备选路径已列
- [ ] 每个要件都能用"有/无"回答
- [ ] 要件—事实—证据三列无空行，或空行已标断点
- [ ] 推理形式与场景匹配（不是一律三段论）
- [ ] 类比论证写了"不同点为什么不影响结论"
- [ ] 法条有争议的写了两种主张
- [ ] 强度评分逐维打分，短板单一
- [ ] 反向压测写了 3 个真会发生的反驳
- [ ] 全文无"显然/众所周知/完全站不住"
- [ ] 编号与案件台账一致，未自造
- [ ] 末尾有律师审核栏

## 6. 异常处理分支

| 异常 | 处理 |
|---|---|
| 找不到请求权基础 | 停止体检，回 `lawyer-legal-research` 先定法律关系；不许硬套相近法条 |
| 要件之间互相矛盾（如既主张买卖又主张赠与） | 列出矛盾点，要求律师择一主张，或写清主备顺位 |
| 证据只能证明"可能" | 如实标低分，并给出"换主张/降请求/先补证"三条路径 |
| 对方可能提出更强类案 | 标 `⚠️ 类案风险`，建议调取该案全文后重评，不臆测裁判结果 |
| 法条刚修订、AI 不确定现行版本 | 标 `⚠️ 条文待核验`，交 `lawyer-source-verify` |
| 客户坚持要一个"稳赢"的说法 | 拒绝给结果承诺；改为"分情形说明：最可能/最好/最坏" |

## 7. 上下游交接

- 需要先查法条、类案 → `lawyer-legal-research`（编号沿用台账）
- 引用需要核验效力与真伪 → `lawyer-source-verify`
- 要件缺证据 → `lawyer-evidence-handling` 补证
- 体检结果要写进文书 → `lawyer-doc-drafting`
- 要转成胜诉概率区间与庭审方案 → `lawyer-litigation-analysis`
- 阶段与期限 → `lawyer-case-workbench` / `lawyer-case-progress`

## 8. 参考资料与本机协作

- 本技能无独立 assets；要件拆解、推理形式、评分表全部内联在第 3 节。
- 本技能为**独立撰写**：用到的是公开法律方法（请求权基础方法、三段论、演绎/归纳/类比/溯因、文义—体系—目的—历史解释），属公共知识；引用的法条为官方文本。未复制任何第三方技能仓库的文本。
- 输出前必过 `lawyer-compliance-guard`（尤其对客户的表述）。
- 案件目录与台账：`lawyer-case-workbench` §3.5。
