# 合同审查（CR-01）

> 程序编号：CR-01（Contract Review）｜触发岗位：授薪律师 / 顾问单位对接律师｜耗时：简单合同 1 小时 / 复杂合同 3-4 小时｜前置：无（客户直接送审即可启动）｜下游：律师审核 → 反馈客户 → 修改后定稿

## 0. 这个技能解决什么

- 痛点：顾问单位一年送审几十份合同，每份都要从头读一遍、逐条比对模板，简单合同也要 1 小时；漏看一个管辖条款或违约金不对等，客户就可能多赔几十万。
- **输入**：合同原文全文、合同类型、我方角色（甲方/乙方）、交易金额与期限、客户最担心什么（选填）、特别关注条款（选填）。
- **产出**：`合同审查报告-CR-YYYYMMDD-序号.md`，落盘到 `案件-<编号>\04-合同审查\`；报告含总体结论（✅ 可以签 / 🟡 修改后可签 / 🔴 不建议签）、风险条款清单与替换文字。
- **不做**：不替客户做商业决策（付款节奏、价格调整是人工确认点）、不判断对方公司真实资信（必须律师去企查查/天眼查核实）、不给"保证没问题"的结论。

## 1. 铁律（违反即失败）

1. **AI 产出只是草稿，必须律师审核签字盖章才能对外。** 审查报告上的"审核律师"栏必须由执业律师填写，AI 只填"AI 辅助草稿"。
2. **法条、案号必须二次核验。** 报告里出现的法律依据要精确到条/款/项并确认现行有效；引用的判例案号必须以裁判文书原文为准，核不了标 `⚠️ 待核实`。
3. **当事人隐私先脱敏再进 AI。** 合同里的自然人身份证号、银行账号、手机号、住址先做占位（`310***1234`、`尾号****`），商业敏感价格可保留但不得外传。
4. **审查结论必须落到"改哪句、改成什么"。** 只写"这里有问题"不算完成，每条 🔴/🟡 都要给出可直接替换的条款文字。
5. **商业条款和法律风险分开写。** 付款节奏、价格、让利属于客户商业判断，AI 只提示风险点，不下商业结论。
6. **编号只来自案件台账。** 待证事实 `TF-01`…、证据 `E-01`…、争点 `IS-01`… 一律以 `案件-<编号>\00-案件档案\案件台账.md` 为准，不得另起编号；报告中引用的条款位置与证据编号必须能在台账找到对应行。台账没有的编号先回台账登记，不许自造。

## 2. 触发条件与输入检查

### 2.1 触发条件
1. 客户拟签合同前送审
2. 合同纠纷发生后倒查条款风险
3. 顾问单位合同批量审查
4. 律所内部模板年度更新

### 2.2 输入检查表（两级门槛）

| # | 输入项 | 级别 | 缺了怎么办 |
|---|---|---|---|
| 1 | 合同原文（全文；拿不到全文时可只给部分条款） | 阻断级（允许部分审查，见下方"部分审查降级"） | 一份都没有 → 退回；只有部分条款 → 不整体退回，走部分审查降级 |
| 2 | 合同类型（借款/合伙/服务/租赁/劳动/医美） | 阻断级 | 退回 |
| 3 | 我方角色（甲方/乙方） | 阻断级 | 退回 |
| 4 | 交易金额、期限 | 可待补级 | 不停工，产出物第一屏登记待补 |
| 5 | 客户最担心什么（资金安全/控制权/退出） | 选填 | 不知道就全面审查 |
| 6 | 特别关注条款（客户点名要看的） | 选填 | 无 |

> **检查动作（两级门槛）**
> 1. **阻断级缺任何一项 → 立即停止**，列出缺项退回，不得先编后补。
> 2. **可待补级缺项 → 不停工**：照常产出，产出物**第一屏**固定写 `⚠️ 本次产出基于 N 项待补信息：<逐项列出>`，并同步登记到案件台账的 `待补` 状态。
> 3. 补齐后重跑并把该行更新为 `已补齐`；未补齐部分不得当作已确认事实。
> 4. 原文"材料给不齐但急着要"的情形走第 2 条，不再另设规则。

**部分审查降级（合同只拿到部分条款）**
> 合同只拿到部分条款（扫描件部分可读、客户只贴了几条）→ **不整体退回**：能读的条款照常逐条审查，无法读取的条款在报告中标 `⚠️ 第 X–Y 条未审（未能读取）`；报告总体结论降级为"**部分审查结论**"，首行注明 `⚠️ 本报告仅覆盖 M 条中的 N 条`。

## 3. 分步程序

**启动前置（先读案件台账）**
- 读 `案件-<编号>\00-案件档案\案件台账.md`；不存在则按 `lawyer-case-workbench` §3.5「案件台账」先建台账再开工。
- 编号原样带入：待证事实 `TF-01`…、证据 `E-01`…、争点 `IS-01`…；本技能只引用、不新编。
- 产出后回写台账：本技能产出物登记到台账"产出物"行，缺项置为"待补"，补齐后更新"已补齐"。

### Step 1：交易结构梳理
**动作**：通读合同，画出交易结构图。
**输出**：
```
谁付钱 → 谁交付什么 → 什么时候交付 → 出问题谁担责 → 争议去哪解决
```
**检查点**：如果合同连"谁付谁钱、付多少、什么时候付"都写不清，先标"⚠️ 核心商业条款缺失"。

### Step 2：主体审查
**动作**：核对签约主体。
**检查项**：
- 对方公司是否合法存续（提示律师去企查查/天眼查核实）
- 签约人是否有权（法定代表人/授权代表）
- 公章是否与合同主体名称一致

**输出**：主体审查结论表（审查项 / 结论 / 待律师核实项）。
**检查点**：签约主体名称、公章、收款账户三者必须一致；不一致标 🔴 并写清差异。

### Step 3：核心条款逐条审查
**动作**：按清单逐条过。
**审查清单**：
| 条款类型 | 审查要点 |
|---|---|
| 标的/数量/质量 | 是否明确、可衡量 |
| 价款/付款方式 | 付款节点是否清晰、发票条款 |
| 履行期限/地点 | 是否具体 |
| 违约责任 | 双方是否对等、违约金是否过高/过低 |
| 解除/终止条款 | 我方有没有单方解除权 |
| 争议解决 | 管辖约定对我方是否有利 |
| 保密/知识产权 | 归属是否清晰 |
| 不可抗力 | 范围是否合理 |

**三色标注规则**：
- 🔴 必须改：不改会出大事（如违约金不对等、管辖在对方所在地、没有退出机制）
- 🟡 建议改：不改有隐患（如付款节点模糊、交付标准不清）
- 🟢 可接受：无明显问题

**输出**：逐条风险清单（条款位置 + 三色等级 + 问题 + 一句话理由）。
**检查点**：🔴 项必须能说出"不改会出什么事"；说不出就降级为 🟡。

### Step 4：缺失条款提示
**动作**：对比标准合同模板，列出这份合同少了什么。
**常见缺失**：
- 税费承担条款
- 通知与送达条款
- 合同生效条件
- 附件清单

**输出**：缺失条款表（缺失项+为什么重要+建议补什么）。
**检查点**：缺失条款表至少覆盖上述四项，缺的写"不适用"，不能整表留空。

### Step 5：个性化风险提示
**动作**：结合本次交易背景，提示特殊风险。
**检查点**：
- 是否存在阴阳合同/黑白合同风险
- 是否存在转包/分包限制
- 是否存在连带责任未限定情形

> ⚠️ **人工确认点**：商业条款（如付款节奏、价格调整）律师自己判断，AI 不替客户做商业决策。

### Step 6：修改建议文字
**动作**：对每条🔴🟡风险，给出具体替换文字（不是说"这里有问题"，而是写"建议改成：……"）。
**输出**：风险条款对照表（原条款 / 问题 / 建议替换文字 / 谈判备选底线）。
**检查点**：每条替换文字必须可直接粘进合同；涉及金额、比例、期限的，写出具体数字占位（如"[30]日内"）。

### Step 7：出具审查报告
**动作**：按模板输出。

**输出**：`合同审查报告-CR-YYYYMMDD-序号.md`，落盘到 `案件-<编号>\04-合同审查\`。
**检查点**：总体结论必须是一句话三选一（✅/🟡/🔴），老板不看正文也能看懂。

## 4. 输出物标准

落盘位置：`案件-<编号>\04-合同审查\合同审查报告-CR-YYYYMMDD-序号.md`。文件名与报告首行编号必须一致。

```markdown
# 合同审查报告 [编号：CR-YYYYMMDD-序号]

## 一、基本信息
- 合同名称：
- 交易金额：
- 履行期限：
- 我方角色：甲方 / 乙方
- 审查日期：

## 二、总体结论
[一句话]：✅ 可以签 / 🟡 修改后可签 / 🔴 不建议签

## 三、主体审查
| 审查项 | 结论 |
|---|---|

## 四、风险条款清单
| 序号 | 条款位置 | 等级 | 风险描述 | 修改建议（替换文字） |
|---|---|---|---|---|

## 五、缺失条款提示
| 缺失条款 | 为什么重要 | 建议补充内容 |
|---|---|---|

## 六、商业条款建议
[付款节奏、违约对等性等]

## 七、特别提示
[结合本次交易的个性化提醒]

审查人：AI 辅助草稿
审核律师：[ ]
```

**部分审查时**：报告首行加 `⚠️ 本报告仅覆盖 M 条中的 N 条`，总体结论写"部分审查结论"，未审条款逐条标 `⚠️ 第 X–Y 条未审（未能读取）`；不得因为部分缺失就整体退回或不出报告。

批量审查顾问单位合同时，逐份输出同名报告，另在目录下加一份 `合同审查台账-CR-YYYYMMDD.md`（合同名 / 结论 / 🔴 数量 / 是否已反馈客户）。

## 5. 质检清单

- [ ] 交易结构一句话说清
- [ ] 主体审查已提示律师去核实对方资质
- [ ] 每条🔴风险都有具体修改文字
- [ ] 违约责任对等性已检查
- [ ] 管辖约定对我方是否有利已写明
- [ ] 缺失条款列出来了
- [ ] 总体结论一句话老板能看懂
- [ ] 商业条款和法律风险分开写，不混
- [ ] 部分审查时已注明未审条款范围，总体结论写"部分审查结论"

## 6. 异常处理分支

| 异常 | 处理 |
|---|---|
| 合同是扫描件/图片无法读取 | 退回，让律师提供可编辑版 |
| 对方是个人不是公司 | 提示律师核实身份证号、住址 |
| 合同涉及刑事风险（如赌博、非法集资） | 明确提示"⚠️ 此合同可能涉及违法，建议不签" |
| 客户要求改的条款明显违法 | 拒绝，并说明法律后果 |
| 合同只有部分条款（扫描件部分可读、客户只贴几条） | 不整体退回：按 §2.2"部分审查降级"处理，能读的条款照审，未审条款标 `⚠️ 第 X–Y 条未审（未能读取）` |

## 7. 上下游交接

**报告完成后的实体去向**
- 报告完成 → 律师审核 → 发给客户
- 客户反馈后 → 出修改版合同（track changes）
- 定稿后 → 归档顾问单位合同台账

**需要其它技能时**
- 需要某一法条原文、类案口径、监管规定 → 回到 `lawyer-legal-research`
- 合同已起纠纷，要评估打不打、怎么打 → 交 `lawyer-litigation-analysis`
- 要出催款/解约/风险告知的律师函 → 交 `lawyer-doc-drafting`
- 纠纷已进入诉讼，要整理合同履行证据 → 回到 `lawyer-evidence-handling`
- 报告要发给客户、对外披露 → 过 `lawyer-compliance-guard`
- 顾问单位合同台账、案件目录与看板 → 见 `lawyer-case-workbench`
- 编号沿用台账，不重新编；交接给下游的编号必须能在 `案件台账.md` 找到对应行（台账规则见 `lawyer-case-workbench` §3.5）。
- 本技能完成 → 交执业律师审核并署"审核律师"；定稿后案件回到 `lawyer-case-workbench` 更新看板

## 8. 参考资料与本机协作

- 本技能无独立 `assets/`，三色标注规则、审查清单、报告模板全部内联在第 3 节和第 4 节；审查时直接按第 3 节清单逐条过，不要凭印象跳条。
- 法条、案号引用前一律二次核验；本文示例中的条款位置、金额、期限都是占位符，示例案号如出现须以裁判文书原文为准，核不了就标 `⚠️ 待核实`，不得编造。
- **输出前必过 `lawyer-compliance-guard`**：审查报告要发给客户前，先过一遍合规闸门（尤其"能不能签"的结论表述）。
- 案件目录、文件命名与看板规则见 `lawyer-case-workbench`。
- 法律依据与类案检索 → `lawyer-legal-research`；合同履行相关证据 → `lawyer-evidence-handling`。
- 案件台账规则见 `lawyer-case-workbench` §3.5「案件台账」：`案件-<编号>\00-案件档案\案件台账.md` 是 `TF-01`…/`E-01`…/`IS-01`… 编号的唯一来源，本技能只读用、不新编。
