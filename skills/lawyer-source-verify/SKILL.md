# 法源与判例核验

> 角色：引证质检员 ｜ 负责：把每一条引用变成"可核实、可追溯、可标注状态" ｜ 不负责：替你判断该主张什么（那是策略层）

## 0. 这个技能解决什么

两个真实风险：
1. **AI 会编法条和案号**——编得很像真的，条号对、表述顺、案号格式也对，但根本不存在。带进法院，是执业事故。
2. **法条会过期、判例会被改判**——引用三年前的条文，对方一句"该条已修订"就把你的整个论证体系打掉。

这个技能**只做一件事**：把所有引用逐条过一遍，给每条标上"来源层级 / 核实日期 / 核实状态"。**核不了的，明确写核不了，不许含糊过去。**

**输入**：待核验的引用清单（或含引用的文书）
**产出**：`法源核验表.md`，落盘 `案件-<编号>\03-法律研究\`

## 1. 铁律（违反即失败）

1. **法条引用三要素缺一不可**：法名全称 + 条/款/项 + 现行有效状态。只写"根据相关法律规定"等于没写。
2. **案号四要素缺一不可**：法院代字 + 年份 + 案号类型 + 编号（例：（2023）粤01民终1234号）。格式不对的一律标 `⚠️ 案号可疑`。
3. **绝不凭记忆生成案号**。AI 不得输出"参考某法院某案号"这种凭印象的引用；没有可靠来源的案号，宁可不写。
4. **来源必须分级**。官方库 > 裁判文书网 > 商业数据库 > 媒体报道。媒体报道的判例只能作方向参考，**不得作为裁判要旨引用**。
5. **每条引用必须有核实日期**。法源会变，没有核实日期的核验等于没核验。
6. **核不了的明说**。写"`⚠️ 本机无法联网核实，须律师在官方库核对`"，不许用推测填空。

## 2. 触发条件与输入检查

### 2.1 触发条件

1. 交起诉状/答辩状/代理词/法律意见书之前
2. `lawyer-legal-research`、`lawyer-legal-reasoning`、`lawyer-doc-drafting` 产出里有引用
3. 客户或对方引用了某条法条/判例，要判断真伪与效力
4. 写公众号/短视频要引用案例（对外发布风险更高）
5. 收到对方的文书，要核对方引用是否成立

### 2.2 输入检查表（两级门槛）

| # | 输入项 | 级别 | 缺了怎么办 |
|---|---|---|---|
| 1 | 待核验的引用清单（法条/司法解释/案号/指导案例） | 阻断级 | 缺了就停；没有清单就先跑 Step 1 抽取 |
| 2 | 引用出现的文书或场景（判断严格程度） | 阻断级 | 必须知道是"交法院"还是"发平台" |
| 3 | 需要核验的时间范围 | 可待补级 | 缺省按现行有效核验 |
| 4 | 是否要评估类案相似度 | 可待补级 | 缺省只核真伪与效力 |

> **检查动作（两级门槛）**
> 1. 阻断级缺项 → 停止。
> 2. 可待补级缺项 → 不停工，首屏写 `⚠️ 本次产出基于 N 项待补信息：<逐项>`。
> 3. 补齐后重跑并更新该行。
> 4. 未补齐部分不得当作已确认。

### 2.3 启动前置

先读 `00-案件档案/案件台账.md`；标注引用与哪条 `TF-` / `E-` / `IS-` 相关，便于回填。

## 3. 分步程序

### Step 1：抽取引用清单
**动作**：把文本里所有引用抽出来，分类列项。
**输出**：
| # | 引用原文 | 类型 | 出现在哪份文件 |
|---|---|---|---|
类型只有五种：**法律 / 司法解释 / 行政法规与部门规章 / 判例（案号）/ 指导案例**。

**检查点**：不要漏"隐性引用"——"根据民法典合同编相关规定""参考同类案件裁判观点"这类模糊表述也要列出，它们是核验重点。

### Step 2：法律条文核验
**动作**：逐条核对五件事。
**核验五问**：
1. **条号对不对**：条、款、项是否准确（第667条 vs 第667条第一款是两回事）
2. **现行有效吗**：是否被修订、是否有新法替代、是否已废止
3. **生效时点**：本案事实发生在该条生效前还是后（涉及新旧法衔接）
4. **表述对不对**：引用的内容与该条实际文字是否一致
5. **有没有配套解释**：该条有无对应司法解释、指导案例改变其适用

**推荐核验渠道**（按权威性排序）：
- 国家法律法规数据库（flk.npc.gov.cn）——法律、行政法规、司法解释
- 最高人民法院官网 / 中国法院网——司法解释全文、指导案例
- 国务院政策文件库、各部委官网——部门规章与规范性文件
- 北大法宝 / 威科先行等商业库（核对快，但标注"商业库来源"）

**输出**：条文核验结果（准确 / 表述有出入 / 已修订 / 已废止 / 无法核实）
**检查点**：标"已修订"的，必须写出修订前后差异与本案适用哪一版本。

### Step 3：司法解释与指导案例核验
**动作**：核对司法解释的文号与效力、指导案例的编号与裁判要点。
**检查点**：
- 司法解释要写法释编号（如"法释〔2020〕17号"），并核对是否被 2020 年后的清理批次修改或废止
- 指导案例要写"指导案例第X号"，核对裁判要点原文
- 会议纪要（如全国法院民商事审判工作会议纪要）不属于司法解释，**不得当作裁判依据引用**，只能作裁判思路参考

### Step 4：判例核验
**动作**：对每个案号做四项判断。
**输出**：
| 案号 | 法院 | 是否真实 | 来源层级 | 审级 | 是否被改判/再审 | 可引用性 |
|---|---|---|---|---|---|---|
**检查点**：
- 案号格式解析：法院代字是否与该法院匹配；年份与编号是否合理
- 只有一审判决的，标注"未生效/可能上诉"，引用价值低
- 已检索不到全文的，标 `⚠️ 来源不可追溯`，不得引用
- 媒体转载的案例，必须找到原始裁判文书才能引用

### Step 5：类案相似度评估（如需）
**动作**：四要素逐项比较，给出参考等级。
**四要素**：
1. **案由**是否相同
2. **基本事实**结构是否相同（金额量级、法律关系、履行方式）
3. **争议焦点**是否相同
4. **法律适用**是否相同（同一条款、同一解释）

**输出**：相似度 `高 / 中 / 低`，并写清"哪一要素不同、为什么差异影响/不影响结论"。
**检查点**：只写"案情类似"不算评估；必须落到四要素。
> ⚠️ **人工确认点**：该判例在本地法院的说服力如何，由律师结合庭审经验判断，AI 不下结论。

### Step 6：引用格式化
**动作**：按裁判文书引用规范整理。
**检查点**：
- 判决书引用法律，应引到具体条款项
- 引用司法解释注明文号
- 引用指导案例注明"指导案例第X号"
- 同一文中同一法条只引一次，不重复堆砌

### Step 7：输出核验报告
**动作**：按 §4 组装，标注总体可信度。
**总体可信度三档**：
- 🟢 可交付：全部引用已核验、来源为官方层级
- 🟡 有条件交付：有引用标"待核实"，但不影响主论证
- 🔴 不可交付：存在无法核实的核心引用（尤其是支撑请求权基础的那一条）

## 5. 质检清单

- [ ] 引用清单完整，含隐性引用（"相关法律规定"类）
- [ ] 每条法条核到条/款/项
- [ ] 每条法条标了现行有效状态
- [ ] 涉及新旧法衔接的写清了适用版本
- [ ] 司法解释写了文号
- [ ] 案号四要素齐全，格式解析通过
- [ ] 每条判例标了来源层级
- [ ] 媒体转载案例未被当作裁判要旨
- [ ] 每条引用都有核实日期
- [ ] 无法核实的已明确标注，未用推测填空
- [ ] 总体可信度已给出并说明理由
- [ ] 没有凭记忆生成的案号

## 6. 异常处理分支

| 异常 | 处理 |
|---|---|
| 本机无法联网 | 全部标 `⚠️ 待人工核验`，输出"核验清单"而非"核验结论"，由律师去官方库补 |
| 法条已废止但对方引用 | 明确指出废止时间与替代条文，写入质证/答辩意见 |
| 案号格式疑似伪造 | 标 `⚠️ 案号可疑`，建议要求对方出示裁判文书原件或申请核实 |
| 判例只有媒体报道 | 标 `媒体转载，不得作为裁判要旨`；若必须用，先找原始文书 |
| 同一问题存在多个相反判例 | 如实列出分歧，写明各自层级与时间，供律师判断，不单方面下结论 |
| AI 对条文表述"记得很像" | 一律标待核验；AI 的记忆不构成核验 |

## 7. 上下游交接

- 需要先找法条与类案 → `lawyer-legal-research`
- 核验后发现法条理解有争议 → `lawyer-legal-reasoning` 做解释路径分析
- 核验通过要写进文书 → `lawyer-doc-drafting`
- 对方引用有问题要写质证/答辩 → `lawyer-evidence-handling` / `lawyer-doc-drafting`
- 对外发布内容引用案例 → 先过 `lawyer-compliance-guard`
- 核实结果回填台账与案件时间线 → `lawyer-case-workbench`

## 8. 参考资料与本机协作

- 本技能无独立 assets；核验五问、来源分级、类案四要素全部内联在第 3 节。
- **本技能为独立撰写**：用到的核验方法与引用规范属公开的执业常识与官方规范；法条、司法解释文本为官方文件，依《著作权法》不受版权保护。未复制任何第三方技能仓库文本。
- 联网核验是本技能的硬缺口：AI 不联网时**只能输出核验清单，不能输出核验结论**。
- 案件目录与台账：`lawyer-case-workbench` §3.5。
