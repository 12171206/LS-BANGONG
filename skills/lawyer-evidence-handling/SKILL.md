# 证据处理工作程序（EV-01）

> 程序编号：EV-01 ｜ 触发岗位：律师助理 / 授薪律师 ｜ 耗时：简单案件 2 小时 / 复杂案卷半天 ｜ 前置：`lawyer-legal-research` 已明确待证事实 ｜ 下游：`lawyer-litigation-analysis`（诉讼分析）/ `lawyer-doc-drafting`（文书起草）

## 0. 这个技能解决什么

- 接案后证据是一堆截图、流水、录音，哪些能用、缺什么、对方会怎么打，全靠律师脑内过一遍——最容易漏，也最容易在庭上被一句"无法核对原件"打掉。
- **输入**：案由、待证事实清单、证据形式（3 项阻断级）+ 当事人已提供的材料清单、对方证据（2 项可待补级，见 §2.2）；**产出**：`证据目录-EV-YYYYMMDD-序号.md`、`质证意见-EV-YYYYMMDD-序号.md`、`补证清单-EV-YYYYMMDD-序号.md`，落盘 `案件-<编号>\02-证据整理\`。

## 1. 铁律（违反即失败）

1. **只整理真实存在的证据，一份都不造** —— 绝不指导当事人伪造、变造、补做证据；当事人提出这种要求立即拒绝，并提示伪造证据的法律后果（罚款/拘留/刑事责任）。
2. **每份证据必须落到具体待证事实** —— 写清证明什么；对应不上待证事实的材料不进证据目录。
3. **编号只来自案件台账。** —— 证据用 `E-01`…、待证事实用 `TF-01`…，一律以 `案件-<编号>\00-案件档案\案件台账.md` 为准；不得在证据目录/质证意见里另起一套编号，台账里没有的编号不许自造，先回台账登记。
4. **原始载体优先，截图只是线索** —— 电子数据未固定的先提醒固定，否则开庭被对方一句"无法核对原件"就可能不被采信。
5. **AI 产出只是草稿，必须律师审核签字盖章才能对外** —— 证据编号与质证意见提交法院前，律师必须核对原始件。
6. **当事人隐私先脱敏再进 AI** —— 姓名、身份证号、手机号、住址、银行账号替换为"甲/乙/某账号"，原件不出本机。
7. **非法取得的证据只提示风险，不替律师决定用不用** —— 偷录、潜入拍摄、私自调取的，列清风险后由律师拍板。

## 2. 触发条件与输入检查

> **启动前置**：先读 `00-案件档案/案件台账.md`（不存在就按 `lawyer-case-workbench` §3.5 建一份）。把本次读到的 TF/E 编号原样带进产出物；产出完成后回写台账对应行的状态（如证据「已固定/待补」、TF「有证据支撑/断点」）。

### 2.1 触发条件

1. 接案后整理当事人零散证据
2. 收到对方证据后做质证意见
3. 证据链不完整时指导当事人补证
4. 刑事案卷阅卷后做证据摘编

### 2.2 输入检查表（两级门槛）

| # | 输入项 | 级别 | 缺了怎么办 |
|---|---|---|---|
| 1 | 案由（决定证明标准） | 阻断级 | 立即停止，退回 |
| 2 | 待证事实清单（要证明什么） | 阻断级 | 立即停止，退回；若 LR 报告/台账已有，可直接从台账读，不必重复问 |
| 3 | 证据形式（书证/电子数据/视听资料/证人证言/鉴定意见） | 阻断级 | 立即停止，退回 |
| 4 | 当事人已提供的证据材料清单 | 可待补级 | 不停工，先出补证清单，并在第一屏标注待补 |
| 5 | 对方证据（如有，做质证） | 可待补级 | 无就只做我方证据 |

> **检查动作（两级门槛）**
> 1. **阻断级缺任何一项 → 立即停止**，列出缺项退回，不得先编后补、不得凭推测开工。
> 2. **可待补级缺项 → 不停工**：照常产出，但在产出物**第一屏**固定写一行：`⚠️ 本次产出基于 N 项待补信息：<逐项列出>`，并把缺项同步写进案件台账的 `待补` 状态。
> 3. 可待补级信息后续补齐后，重跑本技能并把该行更新为 `已补齐`；未补齐的部分不得当作已确认事实使用。
> 4. 原文"材料给不齐但急着要结论"的情形，一律走第 2 条，不再另设规则（消除原文 §2 与 §6 的相互矛盾）。

## 3. 分步程序

### Step 1：待证事实拆解

**动作**：把"我要赢这个官司"拆成具体待证事实单元。

**输出**：
```
待证事实1：[如"原被告之间存在借款合意"]
待证事实2：[如"原告已实际交付9万元"]
待证事实3：[如"被告经催讨未还款"]
```

**检查点**：每个待证事实必须是"有/无"能判断的，不能是模糊的。

### Step 2：证据分组编号

**动作**：把现有证据按待证事实分组，编号。

**编号规则**：证据一、证据二……按时间顺序或按待证事实分组编号。

**输出**：初步证据目录表。

**检查点**：编号连续无跳号；每份证据都挂在 Step 1 的某个待证事实下，同一份证据可复用但只能有一个主编号；重复件、无法辨认件单独标出。

### Step 3：证据三性审查

**动作**：每份证据逐项判断。

**审查维度**：
| 维度 | 判断要点 |
|---|---|
| 真实性 | 原件？原始载体？有无伪造/篡改可能？ |
| 合法性 | 取得方式合法？（偷录/非法入侵取得的可能被排除） |
| 关联性 | 能证明哪个待证事实？ |

**输出**：三性审查表。

**检查点**：审查维度逐项填满，不能整列留空；判断写"认可/不认可/存疑"并附理由，不写空话。

> ⚠️ **人工确认点**：证据取得方式可能违法（偷录、潜入拍摄、私自调取他人账户信息等）时，AI 只列风险与排除可能，是否排除、是否使用由律师判断。

### Step 4：证据链闭环检查

**动作**：画证据链图谱，找断点。

**输出**：
```
待证事实1（借款合意）
├── 证据一：微信聊天记录（证明：被告说"这钱算我借你的"）
└── [断点？] 缺其他佐证

待证事实2（已交付）
├── 证据二：银行转账流水
└── 证据三：微信转账截图

待证事实3（催讨未还）
├── 证据四：催款聊天记录
└── 证据五：通话录音
```

**检查点**：每个待证事实至少要有 1 份证据支撑；没有的 → 列入补证清单。

### Step 5：补证指导

**动作**：告诉律师还缺什么、怎么合法取得。

**输出**：
| 缺什么证据 | 证明什么 | 怎么取得 | 去哪取 |
|---|---|---|---|

**检查点**：必须具体到操作路径（如"微信→我→服务→钱包→账单→下载账单→用做证明材料"），不能说"你去收集一下"。

### Step 6：对方证据质证（如有）

**动作**：对对方每份证据出质证意见。

**输出**：
| 对方证据 | 真实性 | 合法性 | 关联性 | 证明目的是否认可 | 反驳理由 |
|---|---|---|---|---|---|

**质证标准话术**：
- 不认可真实性："该证据为截图，无法提供原始载体，对真实性不予认可"
- 不认可关联性："该证据与本案待证事实无关"
- 不认可证明目的："即使真实，也不能证明对方主张的XX事实"

**检查点**：对方每份证据都要有意见，不能漏项；质证意见不得编造证据内容，不确定的标"⚠️ 待核对原件"。

> ⚠️ **人工确认点**：是否申请鉴定、是否要求对方出示原始载体、是否提出非法证据排除，由律师决定；AI 只提示可行路径与后果。

### Step 7：电子证据固定提醒

**动作**：对当事人特别提醒。

**输出**：口头/微信提醒话术（4 条必提醒项）+ 案件记录留痕。

**必提醒项**：
- 微信聊天：保留原始手机，不删好友、不删聊天，开庭要出示
- 转账记录：去微信支付/银行申请盖章版明细，截图法院可能不认
- 录音：不剪辑、不拼接，整理文字稿
- 网页/广告：公证或时间戳固定

**检查点**：必提醒项 4 条逐条说给当事人，并在案件记录里留痕（谁、何时、提醒了什么）。

## 4. 输出物标准

三个交付件都落盘到 `案件-<编号>\02-证据整理\`，文件名固定：`证据目录-EV-YYYYMMDD-序号.md`、`质证意见-EV-YYYYMMDD-序号.md`、`补证清单-EV-YYYYMMDD-序号.md`（示例：`证据目录-EV-20261031-001.md`）。
编号来源：`00-案件档案/案件台账.md`（E/TF 编号照抄，不自造）；第一屏固定写 `⚠️ 本次产出基于 N 项待补信息：<逐项列出>`，无待补写"无"。

### 4.1 证据目录（法院格式）
```markdown
# 证据目录
案由：[ ]
提交人：原告/被告 [姓名]
编号来源：案件台账（E-01…，不自造）
⚠️ 本次产出基于 N 项待补信息：<逐项列出>

| 编号 | 证据名称 | 证据来源 | 证明内容 | 页数 |
|---|---|---|---|---|
| 证据一 | [ ] | [当事人提供/银行调取] | [一句话证明什么] | |
```

### 4.2 质证意见
```markdown
# 质证意见
针对对方提交的证据，我方意见：
编号来源：案件台账（E-01…；对方证据另编 D-01…，登记后使用）
| 序号 | 对方证据 | 真实性 | 合法性 | 关联性 | 反驳理由 |
```

### 4.3 补证清单
```markdown
# 补证指导清单
- [ ] [证据名称]（证明什么 + 怎么取）
```

## 5. 质检清单

- [ ] 阻断级 3 项输入齐备（可待补级缺项已在第一屏标注 N 项待补）
- [ ] 待证事实拆成具体可判断的单元
- [ ] 每份证据对应明确待证事实
- [ ] 证据链无断点（或断点已列入补证清单）
- [ ] 电子证据固定提醒已写
- [ ] 补证清单具体到操作路径
- [ ] 对方证据质证意见按三性逐项写
- [ ] 没有指导当事人伪造/变造证据
- [ ] 非法证据取得方式已提示风险
- [ ] E/TF 编号与案件台账一致，未自造编号

## 6. 异常处理分支

| 异常 | 处理 |
|---|---|
| 当事人只有截图没有原始载体 | 立即提醒"⚠️ 截图可能不被采信，尽快固定原始手机" |
| 证据是偷录的 | 提示"⚠️ 偷录录音可能因取得方式违法被排除，需评估" |
| 对方证据明显伪造 | 提示律师准备申请鉴定/要求出示原件 |
| 刑事案证据 | 单独标注非法证据排除情形 |
| 当事人问"能不能做假证据" | 明确拒绝，并提示伪造证据的法律后果（罚款/拘留/刑事责任） |

## 7. 上下游交接

- 证据目录完成 → 附在起诉状后提交法院；同批文书交给 `lawyer-doc-drafting`（编号沿用台账，不重新编）
- 质证意见完成 → 庭审时提交
- 补证清单 → 交给当事人去补充
- 证据链完整 → 交给 `lawyer-litigation-analysis`（LA-01 诉讼分析；编号沿用台账，不重新编）
- 待证事实不清或案由判断有误 → 回到 `lawyer-legal-research`（LR-01 法律研究；编号沿用台账，不重新编）重新确认
- 证据目录、质证意见、补证清单的归档位置与命名 → 按 `lawyer-case-workbench` 的案件目录规则

## 8. 参考资料与本机协作

- **本技能暂无独立 assets**；证据规则、微信原始载体、对方截图质证的口径，可直接取 `lawyer-legal-research` 的 `assets/广州地区恋爱转账判例库.md`（案例 5：无法提供原始载体的截图不被采信、伪造证据被罚款；案例 1：事后自认可固定为借款证据）。
- **编号与状态以案件台账为准**：`00-案件档案/案件台账.md` 的字段与维护规则见 `lawyer-case-workbench` §3.5「案件台账」；本技能只引用台账编号、回写状态，不另建编号。
- 输出前必过 `lawyer-compliance-guard`：不得出现结果承诺与"必胜"类表述、当事人信息必须脱敏。
- 案件目录与看板规则见 `lawyer-case-workbench`；落盘目录固定 `案件-<编号>\02-证据整理\`。
- 本技能所有"法院认不认"的判断均为经验口径，正式提交前以律师核对原件、当地法院要求为准；任何举例案号一律标 `⚠️ 待核实`。
