### 2.3 为什么叫这些名字

你原来那套 `lawyer-*` 技能是**前端获客线**（定位、选题、脚本、私信、谈案、跟进）。这次装的是**后端交付线**（案子签下来之后怎么办），所以新技能统一用 `lawyer-` 前缀 + 办案动作命名，并在工作台技能里写清了分工边界：签下来之前走前端族，签下来之后进工作台。两边不会互相抢触发。

## 七、已知限制与这次没做的事（照实说）

1. **法条与案号没有现场核验**。本次没联网，报告里所有法条都标了"须律师二次核验"，判例库的案号是**原包给的**，我只做了原样搬运（哈希一致），没有逐条去裁判文书网验真。开庭前必须核。
2. **飞书多维表没真建**。技能里给了完整字段表 + 三种视图设计，另给了本地兜底的 `案件看板.md`；要真连飞书，得你那边建表后把链接填进去。
3. **建台脚本只在本机 PowerShell 7 上跑过**。已加 UTF-8 BOM 兼容旧版，但没在 Windows PowerShell 5.1 实测。
4. **触发语是中文口语**。你用英文问（"draft a complaint"）可能不触发，加英文触发语即可。
5. **演示案件是虚构的**。里面的金额、判决倾向、调解底线只是演示"这套流程怎么跑"，**不能当成任何真实案件的结论**。
6. **没有版本备份**。6 个技能现在直接生效，改动前建议先备份（第九节给了命令）。

### 12.2 排掉的三个坑

1. **wiki 链接不能直接当 app_token**，要先 `/wiki/v2/spaces/get_node` 换 `obj_token`；节点不是多维表格时（是文档）必须直接告知，不能硬写。
2. **现有 `feishu_bitable.py` 是选题专用 schema**（会建"赛道/评论截图"这类字段），写案件看板会用错；所以新写了中立的 `case-board.py`，复用同一份本机 DPAPI 加密凭据，脚本不打印密钥。
3. **"回读全是 null"是假象**：`list` 默认取前 5 条，那 5 条是原有空行，我的记录排第 6。按 `record_id` 取单条确认数据正确；现在 `list` 会自动计数并跳过空行。
