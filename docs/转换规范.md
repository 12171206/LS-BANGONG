# 律师提效工作台 → DSH 技能：转换规范（作者必读）

本文件是本次"把 5 个 SKILL.md 程序转成本机 DSH 技能"的唯一规范。所有作者严格照此输出，保证 6 个技能风格一致、可被 DSH 正确加载。

## A. 安装位置与目录结构

技能根目录：`%USERPROFILE%\.dsh\skills\<技能名>\`（DSH 的 skill-filesystem 插件自动扫描，`watch: true` 热加载，无需重启）

```
%USERPROFILE%\.dsh\skills\<技能名>\
├── SKILL.md          ← 必须；YAML frontmatter + 正文
└── assets\           ← 可选；参考资料、模板、判例库
```

硬性要求：
- 目录名 = frontmatter 的 `name`，全小写 kebab-case（只允许 `a-z`、`0-9`、`-`）。
- `SKILL.md` 必须在技能目录根上，文件名精确为 `SKILL.md`。
- 文件编码 UTF-8（用 `write` 工具写，不要用 PowerShell `Set-Content` 拼中文，避免 BOM/乱码）。
- 已有技能 `lawyer-*` 家族是"前端获客/内容"线；本次新增的是"后端交付/办案"线，不要改名已被引用的旧技能。

## B. Frontmatter（精确格式）

```yaml
---
name: lawyer-xxx
description: 中文一句话说明 + 触发语（见下规则）
agent_created: true
---
```

`description` 写法（决定这个技能能不能被自动触发，是本文件最重要的部分）：
1. 先写"这个技能干什么、产出什么"，用 `——` 破折号引出。
2. 再写触发语：`当用户说"……""……""……"，或……时使用。` 引号里放律师真实会说的话（口语、短句），至少 4 条。
3. 单行，不换行，不用列表。长度 150–320 汉字之间。
4. 第三人称陈述，不要"我可以帮你……"。

参考（已安装的同类技能）：
- `lawyer-consult-diagnose`：律师咨询诊断与方案设计——……。当用户说"客户要聊聊""怎么做首次咨询""咨询完没下文"……时使用。
- `lawyer-compliance-guard`：律师对外内容、话术、方案的合规闸门——……。当用户问"这句话能不能说""这样写会不会违规"时使用；也是其它技能产出前的必过检查。

## C. 正文结构（固定 9 节，编号照抄）

```markdown
# <中文标题>（<程序编号>）

> 程序编号：LR-01 ｜ 触发岗位：…… ｜ 耗时：…… ｜ 前置：…… ｜ 下游：……

## 0. 这个技能解决什么
- 一句话说明痛点。
- **输入**：……；**产出**：`文件名` + 落盘路径。

## 1. 铁律（违反即失败）
1. …（3–6 条，每条一句加粗判断句 + 一句解释）
必须包含的两条：
- AI 产出只是草稿，必须律师审核签字盖章才能对外；法条、案号必须二次核验。
- 当事人隐私先脱敏再进 AI。

## 2. 触发条件与输入检查
### 2.1 触发条件（编号列表，原文照搬）
### 2.2 输入检查表（Markdown 表格，保留原文每一行：输入项 / 必填 / 缺了怎么办）
并写明检查动作：缺必填 → 立即停止，列缺项退回，不得先编后补。

## 3. 分步程序
每个 Step 一个小节，统一三行结构：
### Step N：<名称>
**动作**：……
**输出**：……（有表格/代码块就把原文搬过来）
**检查点**：……
凡是原文标了 `⚠️ 人工确认点` 的，必须保留，并统一写成：
> ⚠️ **人工确认点**：<原文内容>

## 4. 输出物标准
代码块里放原文的字段级模板（整份报告骨架），路径写在 `案件工作台` 对应子目录。

## 5. 质检清单
- [ ] ……（原文逐条保留，可增不可删）

## 6. 异常处理分支
| 异常情况 | 处理方式 |（原文整表保留）

## 7. 上下游交接
- 本技能完成 → 交给 `<技能名>`（用真实技能名，见 D 节映射）
- 需要某材料 → 回到 `<技能名>`

## 8. 参考资料与本机协作
- 本技能资产：`assets/xxx.md`（说明什么时候读）
- 发到客户/平台前必过 `lawyer-compliance-guard`
- 案件目录与看板规则见 `lawyer-case-workbench`
```

## E. 内容原则

1. **只做转写与增强，不做删减**：原文的步骤、表格、检查点、异常分支、模板全部保留；允许调整顺序使其符合 C 节结构。
2. **不编造法条与案号**。原文里没有的判例不要新增；需要在示例里出现案号的，一律标 `⚠️ 待核实`。
3. **禁止"必胜/稳赢/包赢"类表述**，这也是合规要求。
4. 产出物要"可直接落盘"：写清文件名（如 `法律研究报告-LR-20261031-001.md`）和目录。
5. 每一节都要有可执行动作，不要写空话。
