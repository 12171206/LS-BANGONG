# LS BANGONG · 律师办案工作台（9 个 AI 技能）

> ⚠️ **先读这段**：本项目是律师办案的**流程与文档工具**，不是法律服务，**不构成法律意见**，不建立律师—委托人关系。
> 技能产出全部是 **AI 辅助草稿**，必须经执业律师审核、签字、盖章后才能对外使用；**法条与案号必须二次核验**。
> 仓库不含任何真实当事人信息，示例案件人物情节均为虚构。使用后果由使用者自行承担。详见 [DISCLAIMER.md](DISCLAIMER.md)。

把律师办案的完整链路——**咨询 → 接案 → 取证 → 合同 → 策略 → 立案 → 庭审 → 判决 → 执行 → 结案**——做成 6 个可被 AI 自动触发、按阶段派发的技能。

不是"提示词合集"，而是一套带**输入闸门、人工确认点、质检清单、异常分支、编号台账、律师交付包**的办案操作系统。

> 目标运行环境：**DeepSeek Harness（DSH）**的技能目录（`~/.dsh/skills/`）。技能格式是 YAML frontmatter + Markdown，可移植到其它支持"目录化技能"的 agent 框架。

## 一、包含什么

| 技能 | 干什么 | 关键产物 |
|---|---|---|
| `lawyer-case-workbench` | **总入口 / 派发器**：一键建案件文件夹、按阶段派发技能、维护案件台账与看板 | 10 个标准子目录、案件台账、期限台账、交付包清单 |
| `lawyer-legal-research` | 法律研究：时间线、法律问题拆解、法条与类案、三色风险、接案建议 | `法律研究报告-LR-<日期>-<序号>.md` |
| `lawyer-evidence-handling` | 证据处理：待证事实拆解、编号、三性审查、证据链断点、补证、质证 | 证据目录 / 补证清单 / 质证意见 |
| `lawyer-contract-review` | 合同审查：交易结构、主体审查、条款三色标注、缺失条款、替换文字 | `合同审查报告-CR-<日期>-<序号>.md` |
| `lawyer-litigation-analysis` | 诉讼策略：争议焦点、优劣势、胜诉概率**区间**、庭审提纲、调解两档、风险预案 | `策略分析报告-LA-<日期>-<序号>.md` |
| `lawyer-doc-drafting` | 文书起草：起诉状 / 答辩状 / 律师函 / 代理词 / 法律意见书 | `起诉状-<日期>-v1.md` 等 |
| `lawyer-legal-reasoning` | 论证自检：请求权基础、要件—事实—证据对表、推理形式选择、解释冲突、强度评分、反向压测 | `论证体检表-LG-<日期>-<序号>.md` |
| `lawyer-source-verify` | 法源核验：条款项准确性、现行有效性、案号真伪、来源层级、类案相似度 | `法源核验表-SV-<日期>-<序号>.md` |
| `lawyer-case-progress` | 期限监控：文书→日期、三档视图（今日/本周/30 天）、客户进度话术、风险预警 | `案件进度表.md`、`期限看板.md` |

> 后三个（v1.1 新增）是**独立撰写**的原创技能：分别补上「论证质量」「引证真假」「期限不漏」这三块最容易出事故的环节。写作时只用公开法律方法论与官方文本，不复制任何第三方仓库内容。

技能里还带：

- **案件台账机制**：`TF-01`（待证事实）/ `E-01`（证据）/ `IS-01`（争点）编号只在一处定义，全案文书只读不造 → 不再出现"法律研究说证据一是转账、证据整理说证据一是聊天记录"的错位。
- **台账校验脚本** `check-ledger.py`：编号唯一/连续/可追溯，不通过不许派发下一个技能。
- **一键建台脚本** `new-case.ps1`：建目录 + 播种 9 个模板 + 填好编号与日期。
- **飞书看板脚本** `case-board.py`：把案件写进飞书多维表格（probe / ensure-schema / append / update / list）。
- **律师交付包**：接案到结案必须落到律师手上的 22 项文件（利益冲突审查、委托合同、授权委托书、送达地址确认书、期限与时效台账、证据原件交接单、进度告知书、结案报告……），每项都写了"缺了会出什么事"。

## 二、快速开始

```powershell
# 1. 克隆
git clone <本仓库地址> LS-BANGONG
cd LS-BANGONG

# 2. 安装到本机 DSH 技能目录（默认 ~/.dsh/skills）
pwsh -File .\install.ps1
#   指定目录：pwsh -File .\install.ps1 -SkillsDir "D:\dsh\skills"
#   覆盖已有：pwsh -File .\install.ps1 -Force

# 3. 验证（DSH 里技能目录是热加载的，不需要重启）
#    在 DSH 里问："新案子进来，帮我建案件工作台"
```

手动安装也可以：把 `skills/` 下每个子目录整体复制进你的 DSH 技能目录即可。

### 依赖

| 组件 | 用途 | 是否必须 |
|---|---|---|
| DeepSeek Harness（或兼容的技能目录框架） | 运行技能 | 必须 |
| PowerShell 7（`pwsh`） | 一键建台脚本 | 建台时需要 |
| Python 3.9+ | 台账校验脚本；飞书脚本另需 `requests` | 校验/飞书时需要 |
| 飞书自建应用凭据 | 可选：把案件看板写进飞书多维表格 | 可选 |

> **路径说明**：技能文件里有作者本机的绝对路径（`C:\Users\<user>\.dsh\skills\...`）。`install.ps1` 会在复制时自动改写成你本机的实际路径。

## 四、每个技能的固定结构

每个 `SKILL.md` 统一 9 节，便于校验和二次开发：

```
## 0  这个技能解决什么（输入/产出）
## 1  铁律（违反即失败）
## 2  触发条件与输入检查（两级门槛：阻断级 / 可待补级）
## 3  分步程序（每步：动作 / 输出 / 检查点）
## 4  输出物标准（字段级模板）
## 5  质检清单
## 6  异常处理分支
## 7  上下游交接
## 8  参考资料与本机协作
```

设计上的几个关键取舍：

- **两级输入门槛**：阻断级（研究问题/身份关系/金额/管辖）缺了立即停止；可待补级缺了**不停工**，产出物首屏固定声明"本次产出基于 N 项待补信息"。
- **人工确认点**：11 处 `⚠️ 人工确认点`，全部落在有真实法律后果的分岔口（定性路径、接不接、报价、胜诉概率、调解底线、取证违法性、是否鉴定、商业条款）。
- **概率只写区间**：胜诉概率一律"等级 + 区间 + 依据 + 主要变量"，禁止结果承诺。
- **编号唯一来源**：全案编号只在 `案件台账.md` 定义。

## 五、边界与免责（重要，请读完再用）

1. **所有产出都是 AI 辅助草稿**，必须经执业律师审核、签字、盖章后才能对外使用。
2. **法条与案号必须二次核验**。本套技能不联网核对法条原文，报告里一律标注"须律师核验"；判例库中的案例需自行核实时效与来源层级。
3. **不代拟法律文书条款**。委托代理合同、授权委托书、风险告知书等必须使用你所在律所的正式模板；技能只负责提醒"必须有这一份、该填什么"。
4. **当事人隐私先脱敏再进 AI**。姓名、身份证号、住址、电话、银行账号等按最小必要处理；用 AI 处理材料时保留脱敏映射表。
5. **不构成法律意见**。本项目是流程工具，不提供法律服务，不对任何案件结果作承诺或保证。
6. **判例库会过期**。技能内已加"最后核实日 / 来源层级"字段与 12 个月复核规则，但仍需人工维护。

## 六、安全说明

- 仓库内**不含任何密钥**。飞书脚本从本机加密凭据文件（Windows DPAPI）读取 `app_id` / `app_secret`，支持 `FEISHU_APP_ID` / `FEISHU_APP_SECRET` 环境变量，脚本不打印密钥。
- 发布版已把作者本人的飞书租户、`app_token`、`table_id`、记录 ID 替换为占位符（`<APP_TOKEN>` / `<TABLE_ID>` / `<YOUR_TENANT>`），使用前请填你自己的。
- `docs/演示案件/` 为**虚构案件**，人物为化名，金额情节为示例，不对应任何真实当事人。
